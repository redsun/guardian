METHODOLOGY & SCOPE

Understand the numbers.
Know their limits.

Guardian demonstrates Blend V2 position analysis and hypothetical price / repayment scenarios on Stellar Testnet.

The default position is synthetic. Live mode reads one configured testnet pool using mock oracle prices. This prototype does not connect a wallet, send transactions, monitor positions in the background, or execute automatic protection.

Explore the sample

  1. Click 1. Starting position: 10,000 XLM collateral at $0.20, 1,200 USDC debt, and 50 USDC savings. Displayed health factor: 1.200. Savings do not count as collateral.
  2. Click 2. Price drops 20%. The scenario displays 0.960, below the boundary.
  3. Click 3. Repay 200 USDC. The hypothetical repayment brings the displayed ratio to 1.152. Each walkthrough button loads synthetic data.
  4. Use stress presets, inspect the snapshot, or export it as JSON. “View an address” requests public testnet data.

Risk calculation

The implementation uses integer arithmetic. Collateral rounds down; liabilities round up. The health factor is the ratio of effective collateral to effective liabilities, floored at oracle precision. No debt produces an undefined ratio, displayed as a dash.

underlying collateral = floor(bToken shares × bRate / 10¹²)
underlying debt       = ceil(dToken shares × dRate / 10¹²)
effective collateral  = floor(price × floor(collateral × cFactor / 10⁷) / token unit)
effective liability   = ceil(price × ceil(debt × 10⁷ / lFactor) / token unit)
effective margin      = sum(effective collateral) − sum(effective liabilities)
health factor         = effective collateral / effective liabilities

See Blend’s position calculation and reserve conversions. Local differential tests compare reserve conversions against the installed Blend SDK 3.3.1. This is an estimate using the returned inputs, not a contract execution quote.

Displayed ratios round to three decimals; status uses full fixed-point values, so a displayed 1.000 may be slightly above or below the boundary. Borrowing capacity used means effective liabilities / effective collateral; effective margin is not an amount available to borrow in any particular token.

Simulation assumptions

Only one asset price changes at a time. Other prices, shares, exchange rates, and risk factors remain fixed. Repayment uses hypothetical external funds, is capped at outstanding debt, and converts repayment to debt shares by rounding down. No wallet balance, fee, future interest, pool permissions, or execution timing is modeled.

The price boundary is a downward-only estimate for the selected asset at fixed other inputs. A multi-asset portfolio has no single universal liquidation price. The boundary displayed alongside the scenario is for the original snapshot before repayment.

Failures and freshness

A failed live read returns an error, never synthetic balances disguised as live data. The UI retains and labels the previous snapshot. Live snapshots older than two minutes and active-position oracle prices older than 24 hours are flagged; future oracle timestamps are flagged too. No periodic RPC refresh occurs: reload an address to update its snapshot.

Archived data, pool redeployments, network errors, and unsupported assets can make reads unavailable. Sample data intentionally uses a fixed historical timestamp and remains available offline after the app is served. Inspect the snapshot for all source timestamps and warnings.

Local API

GET /api/position?address=G…
200  PositionSnapshot JSON (no-store)
400  Missing or invalid public G… / C… address
429  Three other reads are in progress
502  Unverifiable or unavailable testnet data

This is a local demo API, with a concurrency cap rather than a production rate limiter. No transaction endpoint is exposed. Run the app from the repository root so the production assets and documentation can be served.

A stalled read returns 504 after 75 seconds. Outstanding upstream work remains counted until it settles. GET /healthz reports service availability without reading the chain.

Testing and evidence

Run npm run check for repository language, deterministic tests, type checking, and production builds. Build first, then run npm run test:e2e for desktop/mobile browser flows. Browser API responses are fixtures and do not prove live connectivity.

Run npm run verify:live -- --capture to check the configured testnet position and save a snapshot with its hash and provenance. See testing and verification for reproducible checks and historical testnet evidence for the included capture. A past capture does not establish current availability.
